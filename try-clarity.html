Guided quick assessment

Try Clarity on one live claim.

This workflow now follows the framework directly: claim, posture, evidence, assumptions, confidence, ownership, monitoring, triggers, reassessment, and a generated recommendation.

Runs locally in your browser. No account, no backend, no server submission. The report is generated on-device and exported only if you choose to save it.

Phase 1

State the claim

Start with one claim, not a whole project. If the claim is unclear, the rest of the assessment will be weak.

Examples: Customers want Feature X. This architecture will scale. This release is production-ready.

Which posture best matches the claim right now?

Why this exists

Is a decision or live commitment required now?

Phase 2

Justify the claim

Separate support from assumption, then check whether confidence is outrunning the evidence.

How confident are you relative to the current evidence?

Confidence debt check

How correctable is action if the claim is wrong?
Why this exists: Correctability calibrates how much evidence is needed before commitment. Low correctability means recovery is hard, expensive, or slow if the claim is wrong.

Phase 3

Define monitoring and triggers

The framework treats triggers as claims too. A useful trigger names what you watch, what threshold matters, why it matters, and how you will respond.

State the trigger claim explicitly: what does crossing this threshold mean?

Phase 4

Review the recommendation

The recommendation is generated from posture, evidence confidence, decision pressure, and correctability. You can add a practical note if the default recommendation needs context.

Reflection Questions

  • Does confidence exceed what the evidence can currently justify?
  • Are assumptions being treated as facts?
  • Who owns the consequences if the claim is wrong?
  • What would force immediate response versus deeper reassessment?
  • What would invalidate the trigger model itself?
